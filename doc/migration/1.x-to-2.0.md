# Migrate `flutter_fusioncharts` from 1.x to 2.0

Most constructor call sites remain source-compatible. Complete the steps below
before upgrading.

## Summary

| | 1.x | 2.0 |
|---|---|---|
| WebView | `flutter_inappwebview` | `webview_flutter` |
| Flutter | `>=1.17.0` (declared) | `>=3.3.8` |
| Dart | `>=2.18.4 <3.0.0` | `>=2.18.4 <4.0.0` |
| FusionCharts | Application assets or CDN | FusionCharts 4.2.2 bundled |

The 1.x Flutter declaration was broader than its Dart requirement: Dart
`>=2.18.4` prevented older Flutter releases from resolving the package.

## Breaking changes

### Remove `setWebViewController`

Delete calls to the removed method:

```dart
// 1.x - remove this call
controller.setWebViewController(inAppWebViewController);
```

2.0 manages the WebView internally. There is no replacement for direct WebView
access. This is the only unavoidable compile-time API break.

### Replace `isLocal: false`

In 1.x, `isLocal: false` loaded FusionCharts from the CDN. In 2.0 it reports
`unsupported-source` and loads nothing.

Remove the parameter and use the default package assets:

```dart
FusionCharts(
  type: 'column2d',
  dataSource: data,
  onError: (FusionChartsError error) {
    debugPrint('${error.code}: ${error.message}');
  },
);
```

The package includes FusionCharts 4.2.2, its modules, eight themes, and the
World and USA maps. You can remove equivalent application-supplied files.

Keep any other map definitions or custom files. Load them through an
application-owned asset page as described in [API changes](#api-changes).

## Platform settings

- **Android with Flutter 3.3.8:** use `minSdkVersion 19` or newer,
  `compileSdkVersion 33` or newer, and JDK 17. Newer Flutter versions can
  require newer Android settings.
- **Android network settings:** remove
  `android:usesCleartextTraffic="true"` if it was added only for the 1.x CDN.
- **iOS:** remove the `NSAppTransportSecurity` exception if it was added only
  for the 1.x CDN. Use the deployment target required by your Flutter SDK.
- **Storage permissions:** remove `MANAGE_EXTERNAL_STORAGE`,
  `WRITE_EXTERNAL_STORAGE`, `READ_EXTERNAL_STORAGE`, and
  `ACCESS_MEDIA_LOCATION` unless your application needs them independently.

## API changes

| Status | API |
|---|---|
| Retained | `dataSource`, `type`, `height`, `width`, `events`, `fusionChartEvent`, `fusionChartsController`, `streamController`, `timeSeriesSchema`, `timeSeriesData`, `licenseKey` |
| Retained but deprecated | `isLocal`; omit it and use the package assets |
| Retained controller methods | `executeScript`, `addEvents`, `removeEvents` |
| Added | `source`, `onError`, `onExport`, `setData`, `feedData`, `exportChart`, `isReady` |
| Removed | `setWebViewController` |

`fusionChartEvent` keeps the 1.x argument order `(senderId, eventName)`.
`source` takes precedence over `isLocal`. Prefer typed controller methods over
the advanced, unsafe `executeScript` method.

For an application-owned HTML page, declare the page and all referenced files
as Flutter assets:

```yaml
flutter:
  assets:
    - assets/fusioncharts_page.html
    - assets/fusioncharts/
```

Then select it explicitly:

```dart
source: FusionChartsSource.asset(
  assetKey: 'assets/fusioncharts_page.html',
),
```

## Behavior changes

| 1.x behavior | 2.0 behavior |
|---|---|
| Property changes after the first build were ignored | Chart data, type, dimensions, source, and controller update correctly |
| Multiple charts interfered with each other | Multiple charts work independently |
| The widget embedded its own `Scaffold` | The chart composes inside existing layouts |
| Stream subscriptions remained active after disposal | Subscriptions are cancelled |
| Map chart types could silently switch to CDN | The requested source is preserved |
| JPG export could produce a PDF | Export uses the requested supported format |

Give every chart a definite height. It fills its parent, so an unbounded parent
can collapse it to zero height.

## Export changes

2.0 returns export bytes through `onExport`. It does not write files, request
storage permissions, or use a network export server.

```dart
FusionCharts(
  type: 'column2d',
  dataSource: data,
  fusionChartsController: controller,
  onExport: (FusionChartsExport result) {
    // Save or share result.bytes in your application.
  },
);

controller.exportChart(FusionChartsExportFormat.svg);
```

| Format | Android | iOS |
|---|---|---|
| SVG, CSV, XLSX | Supported | Supported |
| PNG, JPG, PDF | Supported | Not supported |

PNG, JPG, and PDF export is unavailable on iOS in 2.0.0. Requests report
`export-unsupported`.
